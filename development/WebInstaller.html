This is the specification for a new web installation tool for FluidNC.

Technology

Uses esptool-js - which in turn uses WebSerial - to download FluidNC images to an ESP32.  WebSerial currently works on Chrome, Edge, and Opera browsers. 

The page will be hosted on GitHub Pages with the code in a repo under github.com/bdring .

The URL will be installer.fluidnc.com

User Interface

The visual design of the user interface is TBD.  Whoever takes up this project will have leeway to design the layout / look and feel (but we discourage the use of enormous frameworks, preferring relatively simple HTML/Javascript).

Functionally, we need the following features:

  • Display a list of the last 5 or so FluidNC releases (with the option to go farther back) and let the user choose one. (REST API: https://api.github.com/repos/bdring/FluidNC/releases returns a JSON-encoded array of release information)
  • Alternatively, the user can choose a prerelease or test build (REST API: The “prelease:” tag in the JSON array is true for prereleases and false for initial releases)
  • After a release has been selected, the list of images that can be installed will be displayed.  Those things can include
    • Wifi firmware
    • Bluetooth firmware
    • Local filesystem
    • From-scratch installation of firmware plus local filesystem - which loses existing files like config.yaml
    • Options to use alternate partition schemes for ESP32s with larger FLASH sizes. Currently the extra space is not used.  This is made more complicated by the fact that the firmware image base address must be consistent with the partition layout.  So this feature might be deferred until later.
    • (Future) images for other ESP32 variants like ESP32-S3
    • (REST API: The JSON data has, for each release, an “assets” array.  Each asset entry has a name like “wifi-firmware.elf” and a  “browser_download_url" that tells you where to get the asset.  We can come up with a naming scheme that identifies which ESP variants are supported)
  • After the user has chosen exactly what to install, an Install button will be activated

Development Status

There is a simple proof of concept -  source code . live page .  It was created by copying the esptool-js code and making simple mods to the UI (index.html and index.js files).  When you host on GitHub pages, the “normal” way is to use Jekyll to create a static site, but as an alternative, you can bypass Jekyll and just put your own index.html and whatnot in the repo, using a GitHub action to “deploy” the files in the repo to the hosting site.  That alternative is what we use.

Progress 2023-1-21: The POC now lets you choose a release and displays its assets.

Progress 2023-3-7: Joacim Breiler has picked up development of this feature.  His current work in progress can be found at https://breiler.github.io/fluid-installer/

Next Steps

We should change the FluidNC release scripts to expose individual files as assets instead of bundling them in .zip files.  There should be a manifest.json that provides metadata about the files, including their ESP32 variant, load address, MD5 or other verifier, …  The manifest would let the installer organize the asset display and automatically set the options for the download-to-ESP32 step.  If you have already connected to the ESP32, the installer could know which ESP32 variant is present, displaying only appropriate images.
